# Agent 调用合约

本目录是可搬移的、本地只读风味证据数据库。先读本文件，再读 `README.md`；字段以 `schema.sql`、`DATA_DICTIONARY.md` 为准，调用示例见 `QUERY_EXAMPLES.md`。此文件约束对证据的使用，不代替用户对任务的指示。

## 开始每项任务

1. 先查询数据库版本、来源范围、记录数与校验结果，再检索原料名称。不要凭记忆写入食材 ID。
2. 从检索结果取得稳定 `ing-…` ID，再读取该 ID 的全部原始记录、版本、未知项与冲突。名称只用于检索；两个 ID 即使显示名相同，也不得合并。
3. 查阅适用的文字证据、加工记录与原始出处，分别保留直接名称匹配和相关语境。对照品种、部位、状态、基质、温度、时间、设备、测定方法、单位和分母。
4. 输出任何结论时带上食材 ID、证据或加工记录 ID、出处、条件与限制。无法匹配、缺少条件、未测量时明确写明；不得用 `0` 补齐。

## 身份、圆点与多版本

- `ingredients.id` 是稳定身份键；别名表只帮助查找。`display_name`、加工索引中的来源名称组、视觉家族均不是可合并身份的依据。
- `recommendation_eligible=0` 的名称待审或教学身份可检索和引用，不能作为自动推荐的正常候选。记录级身份标志与教学标志也必须保留。
- 每条圆点记录有 14 个来源类别。`presence=1` 是原表该类别有标记；`presence=0` 是未标记；`NULL` 是未知或无法可靠判读。未标记不等于无香气、无分子、零浓度或感官不可察觉。
- `shared_with_main=1` 是该配对表语境中与主食材共享分子的标记。它不是浓度、分子数量、搭配分数或好吃概率。主行这一字段通常不适用，为 `NULL`。
- 保留所有来源版本。不得用历史 `canonical` 字段、投票、最大值、均值或任意一行替代所有记录。`canonical` 只留在原始 JSON 中作为历史资料，不是推荐用的测量向量。
- 冲突和未知可以同时存在。汇总状态为 `conflict` 时仍需输出 `unknown_count` / `has_unknown`；不要只读一个状态字符串。
- 配对有来源方向：主食材 → 同表配对行。查询可同时查两种方向，但不得将多个表合并成新测量，不得由 A–B、B–C 推出 A–C。
- 9,480 条目录配对加 10 条恢复的教学配对，共 9,490 条；这不是 9,490 个不重复的无向食材对。教学配对必须显式标注并从默认推荐中排除。

## 证据关联与加工层

- `exact_name`：来源名称完全匹配；`alias_name`：经别名匹配；`related_context`：相关上下文、上下位或处理状态提及。前两者仍须核对具体状态，均不授权把数值移植到其他品种或条件。
- `related_context` 必须单列，不能当作该食材已经实测。原始 `raw_json` 中的 `contextScope`、`quantitativeTransferAllowed`、匹配原因应随证据保留。
- `descriptor_mentions` 只表示文字提及，可能来自否定、对比、例子或条件句；不等同于属性存在。证据主题标签也只是检索导航。
- 加工层包含前后变化、加工后状态描述、条件依赖及研究摘要。`record_kind` 为状态描述时，不得臆造加工前基线或因果增量。
- 相近效果按“维度 + 标签 + 方向”分组。增加、形成、减少、保持、未发现显著变化、未知或条件依赖须分别处理。相似标签不证明相同机制或相同幅度。
- 味觉甜度、焦糖/甜香、三叉神经刺激、质地、化学指标、感官喜好是不同维度。GC–MS 相对峰面积、挥发物释放量、OAV 和感官强度不可互换。
- “未发现显著变化”不等于证明没有变化；“未报告”不等于零；“未测定”不等于无。不得凭定性资料生成任意温度–时间曲线或风味百分比。
- 按食材索引的 154 个组是来源名称导航组，不是数据库的 1,474 个稳定食材身份；同一记录可以出现在多个方式、效果或名称组中。统计记录数须 `COUNT(DISTINCT processing_id)` 或 `COUNT(DISTINCT id)`。

## 来源与结论的边界

- 原书 `pdf_page` 是 PDF 文件页序，`book_page` 是印刷页码；不可混用或假定全部相差固定值。缺少印刷页码保留 `NULL`。
- 研究记录是当前已整理的研究级结论和报告数值，尚不是各论文完整的原始实验矩阵。引用题名、DOI/URL、实验条件与 `extractionScope`，不得称其已完成全部论文原始数据提取。
- 当前库保存现有抽取结果，不代表全书所有图表文字已穷尽，也不代表全部圆点逐格人工复核或科学结论已被独立重复实验。
- 保留原文中的不确定性、测量方式、统计结论、样本条件、浓度单位和分母。书中百分比与研究论文百分比即使相似也不得自动认定为同一测量。
- 数据库引用外部 PDF，未把书的 PDF 嵌入数据库；已收入 392 页抽取文字供上下文检索。抽取文字不替代原图表，不按固定偏移推算印刷页。搬移数据库后可继续查询结构化资料、书页文字与图片；打开原书需要另行提供该 PDF。

## 三类创新任务

- **按目标找原料**：分开检索原表类别标记、文字提及和加工效果；保留全部来源版本与候选资格。可提出目标覆盖假设，不能把圆点比例写成风味强度。
- **替换食材**：对照原料状态、多版本标记、文字/加工证据、用量功能与口感条件。相似类别仅是候选依据，不能推导等量替换、营养等价、过敏安全或感官等价。
- **组合新配方**：使用有出处的配对和加工证据提出试配方案；配比是试验建议，风味结果尚待实做和感官验证。新推断与库中来源事实分栏或明确标识。

推荐单条输出结构：

```json
{
  "ingredient_ids": ["由检索结果取得的稳定 ID"],
  "record_ids": ["来源圆点行 / E… / 加工记录 ID"],
  "claim": "证据支持的结论或明确标注的试配假设",
  "claim_type": "source_statement | study_summary | agent_hypothesis",
  "sources": [{"pdf_page": null, "book_page": null, "doi_or_url": null}],
  "conditions": "适用状态、温时、设备、基质和测定语境",
  "limitations": ["未知、冲突、未报告条件及不可外推事项"]
}
```

此结构是输出建议，不是数据库的新测量记录；字符串占位值须替换为实际检索结果。

## 文件与资产操作

- 常规调用只读。使用提供的只读接口或 SQLite `mode=ro`，不得直接写入、删行、改标记、覆盖未知或“修复”来源冲突。
- 若用户要求修订证据，修改有审计记录的来源文件，再运行重建与完整校验；保留原始证据。运行时不依赖源 JSON，但重建依赖源工作区。
- 图片已作为 BLOB 嵌入。食材 SVG 是程序绘制的示意资产；草莓主视觉是一张 AI 生成图片。它们都不是原料真实照片、品种鉴定或形态测量证据。
- 原 JSON 的 crop_path、sourceCropPath 等复核截图引用保留原路径；裁图本身未嵌入，不把搬移后路径当作可用图证。
- 用原资产 MIME 类型与校验值导出。`sha256` 验证字节一致性，不证明内容科学正确或人工复核完成。
- 不把用户的试配结果或生成的新假设写入此证据库。若需要记录，另建带来源和验证状态的实验/候选文件，并由用户决定是否纳入后续版本。
